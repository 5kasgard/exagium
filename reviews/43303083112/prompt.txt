36:   E and F answered a one-line probe on 2026-11-11. `gemma-4-31b-it:free` was probed and returned an upstream rate limit (1 of 1), so it isn't an arm. Cloudflare Workers AI isn't an arm: its free 10,000 neurons a day is below one attempt's uncached prompt tokens at the listed rates (bench-2's smallest attempt read 0.28M prompt tokens; a listed mid-size model costs 40,000 neurons per million). That is arithmetic from the price list, not a test.
37: - **Batches sized to the measured allowance.** Each batch asks the provider how many free requests are left, plans `(left − 20) // 80` attempts (at most 12), and each attempt checks again and is skipped under 180. A skipped attempt is not a result. Batches run twice a day until no cell is open. Order: controls, then repeat 1 of every task and arm, then repeat 2, and so on.
38: - **Provider cuts are retried.** An attempt ending in a provider error (rate limit, quota, auth, timeout, 5xx) is not counted and its cell is retried in a later batch. After 3 cuts the cell is recorded as `provider_cut` and left out of every denominator.
39: - **Futility stop.** An arm with 0 clean passes in its first 6 counted attempts, in planned order (repeats 1 and 2 of each task), stops (0 of 6 puts its rate under 46% at 95%).
40: - **Network seal.** On the runner, traffic leaving any container is refused except DNS and Cloudflare's published address ranges, which hold the model provider. Before each attempt a container must reach the provider and be refused by github.com, or the attempt doesn't start. Refused connections are counted; the count includes the harness's own refused calls (12 in the pilot, all to GitHub's raw-file hosts, none from an agent action). Limit: other sites behind Cloudflare stay reachable, so the bench-2 clean rule still applies as well.
41: - **Snapshots.** `run_agent.py` copies the workspace's `record/` each time its contents change, with the number of actions so far. Afterwards each copy is graded by the agent's own test file ("visible") and by the grader ("hidden"). The agent never sees this. Limit: only `record/` is snapshotted; the rest of the tree is taken from the end state.
42: - **Measures fixed:** the diff counts content lines only; model calls are the distinct response ids in the event log; the control has its own label.

44: ## Endings (one per attempt; the first match wins)
45: 1. `control`: the no-agent arm.
46: 2. `skipped_budget`: the allowance guard refused it. Not a result.
47: 3. `timeout`: the 35-minute cap killed it (exit 124 or 137). Counted as a fail.
48: 4. `harness_crash`: an exception outside the agent loop, or no run record.
49: 5. `provider_error`: see above. Not counted; retried.
50: 6. `iteration_cap`: SDK code `MaxIterationsReached`. Not a crash.
51: 7. `stuck`: the SDK's stuck detector ended it. Not a crash.
52: 8. `finished`: status finished, with no error.
53: 9. `unclassified`: anything else. **Counted as a crash,** and each one is reported with its error text.

55: ## Decisions, fixed now
56: - **Counted attempts** are endings 3, 4, 6, 7, 8 and 9. The first counted result for a cell stands.
57: - **Clean** means the agent's actions fetched no URL and its actions or observations named no host path, as in bench-2. A **clean pass** is a clean attempt whose hidden test passes with no pass-to-pass test broken.
58: - **Seal holds** if no counted attempt names a host path. If any does, W is void.
59: - **H1″:** the share of counted attempts that are not `harness_crash` or `unclassified`. **Holds** at 7/9 or more, **fails** at 4/9 or less, else **inconclusive**; inconclusive under 5 counted attempts. Compared as exact fractions.
60: - **W, per arm:** clean passes over counted attempts (crashes and timeouts count as fails, since in real use the task wasn't done), with a Clopper-Pearson 95% interval.
61:   - **Usable** holds if the interval's lower end is 50% or more, fails if its upper end is under 50%, else inconclusive.
62:   - **Ranking:** arm X is above arm Y only if X's lower end is above Y's upper end. Nothing else is claimed about order.
63: - **S:** over clean passes that have a visible-green snapshot with `record.py` changed: *kept* means the hidden test also passes at that first snapshot; *saving* is `1 − actions at that snapshot / actions in the attempt`.
64:   - **Holds** if there are at least 8 such attempts, at least 90% kept, and the median saving is at least 20%.
65:   - **Fails** if under 75% kept or the median saving is under 10%. Else **inconclusive**.
66:   - It is a measurement of what a stop rule would have done. No attempt is actually stopped.
67: - **Budget:** report median calls per counted attempt, per arm and overall, and calls per clean pass. Calls spent in provider-cut attempts are reported apart. No threshold.
68: - **Void:** if any control passes, the status says VOID and no verdict stands.
69: - **Also reported, with no verdict:** the share of an attempt's actions that came after the hidden test first passed (the most any stop rule could save).
70: - Verdicts are final only when the status says complete. Until then the status is marked provisional.

75: ## Known limits, stated now
76: - Three tasks, all in one file (`record/record.py`), all from this repo's public history. A model trained on the repo after the fixes could know them. Rates here are for this kind of task.
77: - Attempts on the same task are not independent draws of "a task"; the interval describes repeat runs of these three.
78: - Calls counted from response ids miss retries that produced no event. The provider's own count of requests left is recorded before each attempt.
79: - A 35-minute timeout leaves no record of its cause. If the provider hung, the attempt still counts as that worker's fail; timeouts are listed per arm so this can be seen.
80: - Free model listings change; a model that disappears mid-run shows up as provider cuts.
81: - The pilot (one attempt and one control, `mode=pilot`) checks the instruments and counts for nothing.
