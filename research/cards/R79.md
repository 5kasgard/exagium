## Opinion (5)
- **failure mode**: Dynamic tracking of syscalls may miss some calls, preventing a complete allowlist. — "dynamic tracking is a straight‑forward approach but it cannot get the full syscall list." [preprint: Shrinking the Kernel Attack Surface Through Static and Dynamic Syscall Limitation, 2025; (link refused)]
- **failure mode**: Static analysis alone over‑approximates the syscall list, producing many false positives. — "Static analysis can construct an over‑approximated syscall list, but the list contains many false positives." [preprint: Shrinking the Kernel Attack Surface Through Static and Dynamic Syscall Limitation, 2025; (link refused)]
- **method**: Chestnut extracts used syscalls statically via a compiler and a binary analyzer. — "Chestnut comprises two phases, with the first phase consisting of two static components, i.e., a compiler and a binary analyzer, that statically extract the used syscalls." [paper: Automating Seccomp Filter Generation for Linux Applications, 2021; https://doi.org/10.1145/3474123.3486762]
- **method**: An optional dynamic refinement phase can further restrict the allowed syscall set. — "An optional second phase of Chestnut is dynamic refinement to restrict the set of allowed syscalls further." [paper: Automating Seccomp Filter Generation for Linux Applications, 2021; https://doi.org/10.1145/3474123.3486762]
- **method**: Timeloops learns allowed syscalls at runtime while rejecting spurious calls. — "Timeloops automatically learns which system calls a program should be allowed to invoke while rejecting attempts to call spurious system calls." [paper: Timeloops: Automatic System Call Policy Learning for Containerized Microservices, 2022; https://doi.org/10.48550/arxiv.2204.06131]
