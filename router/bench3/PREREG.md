# Pre-registration: bench-3, repeats, five free workers, and where an attempt first goes green

Written 2026-11-11 before any registered run. Author: Claude (chose the setup and the arms; not an arm). It follows `router/bench2/RESULTS-2.md`.

**Every rule below is code in `router/bench3/decide.py`.** `decide.py selftest` runs before each batch and checks that every possible ending gets exactly one label and every rule returns a verdict. Where this text and the code differ, the code is the rule and the difference is a defect to report. The status table (`router-runs:bench/bench3/STATUS.md`) is generated by that code, not written by hand.

## Why
bench-2 gave one attempt per task per model. Its intervals overlap (3 of 3 is 29–100% at 95%; 0 of 3 is 0–71%), so it can't rank workers or fill a spec card. Both earlier benches also had an ambiguous rule and three measurement bugs each.

## Questions
- **W. Worker rates.** For each free model, what share of attempts ends in a clean pass, with an interval?
- **S. Stop on green.** Would stopping an attempt when its own tests first pass (after it changed `record.py`) keep the pass, and how many actions would it save?
- **Seal.** Does the agent stay inside its workspace, now with the network closed too?
- **H1″. Harness.** Does the Agent Server (SDK v1.61.0) run attempts without crashing?
- **Budget.** Model calls per attempt, per worker, and calls per clean pass.

## Same as bench-2
- Tasks T1–T3, task text, grader (`router/bench/grade.py`), hidden tests and pass-to-pass lists.
- SDK v1.61.0 and image `agent-server:1.61.0-python`, default agent, iteration cap 80, 35-minute cap per attempt.
- The workspace is the only mount; the full checkout is deleted before the agent starts.
- The no-agent control Z runs once per task and must fail all 3, or the run is void.
- Free models only; the workflow refuses any slug that doesn't end in `:free`.

## Changed, and why
- **Repeats:** 5 attempts per task per arm, 15 per arm, 75 in all.
- **Arms** (each from a different vendor; A, B and D carry over):

  | Arm | Model | Vendor |
  |---|---|---|
  | A | `nemotron-3-ultra-550b-a55b:free` | NVIDIA |
  | B | `flint-v1.0:free` | Recursive |
  | D | `north-mini-code:free` | Cohere |
  | E | `ernie-5.5-flash-preview:free` | Baidu |
  | F | `dots-3-note-preview:free` | Dots Studio |

  E and F answered a one-line probe on 2026-11-11. `gemma-4-31b-it:free` was probed and returned an upstream rate limit (1 of 1), so it isn't an arm. Cloudflare Workers AI isn't an arm: its free 10,000 neurons a day is below one attempt's uncached prompt tokens at the listed rates (bench-2's smallest attempt read 0.28M prompt tokens; a listed mid-size model costs 40,000 neurons per million). That is arithmetic from the price list, not a test.
- **Batches sized to the measured allowance.** Each batch asks the provider how many free requests are left, plans `(left − 20) // 80` attempts (at most 12), and each attempt checks again and is skipped under 180. A skipped attempt is not a result. Batches run twice a day until no cell is open. Order: controls, then repeat 1 of every task and arm, then repeat 2, and so on.
- **Provider cuts are retried.** An attempt ending in a provider error (rate limit, quota, auth, timeout, 5xx) is not counted and its cell is retried in a later batch. After 3 cuts the cell is recorded as `provider_cut` and left out of every denominator.
- **Futility stop.** An arm with 0 clean passes in its first 6 counted attempts stops (0 of 6 puts its rate under 46% at 95%).
- **Network seal.** On the runner, traffic leaving any container is refused except DNS and Cloudflare's published address ranges, which hold the model provider. Before each attempt a container must reach the provider and be refused by github.com, or the attempt doesn't start. Refused connections are counted. Limit: other sites behind Cloudflare stay reachable, so the bench-2 clean rule still applies as well.
- **Snapshots.** `run_agent.py` copies the workspace's `record/` each time its contents change, with the number of actions so far. Afterwards each copy is graded by the agent's own test file ("visible") and by the grader ("hidden"). The agent never sees this. Limit: only `record/` is snapshotted; the rest of the tree is taken from the end state.
- **Measures fixed:** the diff counts content lines only; model calls are the distinct response ids in the event log; the control has its own label.

## Endings (one per attempt; the first match wins)
1. `control`: the no-agent arm.
2. `skipped_budget`: the allowance guard refused it. Not a result.
3. `timeout`: the 35-minute cap killed it (exit 124 or 137). Counted as a fail.
4. `harness_crash`: an exception outside the agent loop, or no run record.
5. `provider_error`: see above. Not counted; retried.
6. `iteration_cap`: SDK code `MaxIterationsReached`. Not a crash.
7. `stuck`: the SDK's stuck detector ended it. Not a crash.
8. `finished`: status finished, with no error.
9. `unclassified`: anything else. **Counted as a crash,** and each one is reported with its error text.

## Decisions, fixed now
- **Counted attempts** are endings 3, 4, 6, 7, 8 and 9. The first counted result for a cell stands.
- **Clean** means the agent's actions fetched no URL and its actions or observations named no host path, as in bench-2. A **clean pass** is a clean attempt whose hidden test passes with no pass-to-pass test broken.
- **Seal holds** if no counted attempt names a host path. If any does, W is void.
- **H1″:** the share of counted attempts that are not `harness_crash` or `unclassified`. **Holds** at 7/9 or more, **fails** at 4/9 or less, else **inconclusive**; inconclusive under 5 counted attempts. Compared as exact fractions.
- **W, per arm:** clean passes over counted attempts (crashes and timeouts count as fails, since in real use the task wasn't done), with a Clopper-Pearson 95% interval.
  - **Usable** holds if the interval's lower end is 50% or more, fails if its upper end is under 50%, else inconclusive.
  - **Ranking:** arm X is above arm Y only if X's lower end is above Y's upper end. Nothing else is claimed about order.
- **S:** over clean passes that have a visible-green snapshot with `record.py` changed: *kept* means the hidden test also passes at that first snapshot; *saving* is `1 − actions at that snapshot / actions in the attempt`.
  - **Holds** if there are at least 8 such attempts, at least 90% kept, and the median saving is at least 20%.
  - **Fails** if under 75% kept or the median saving is under 10%. Else **inconclusive**.
  - It is a measurement of what a stop rule would have done. No attempt is actually stopped.
- **Budget:** report median calls per counted attempt, per arm and overall, and calls per clean pass. No threshold.
- Verdicts are final only when the status says complete. Until then the status is marked provisional.

## Spend
$0. OpenRouter free models only. Worst case 75 × 80 = 6,000 requests over about 6 days; expected about half that. GitHub-hosted runners, for this project's own development and testing.

## Known limits, stated now
- Three tasks, all in one file (`record/record.py`), all from this repo's public history. A model trained on the repo after the fixes could know them. Rates here are for this kind of task.
- Attempts on the same task are not independent draws of "a task"; the interval describes repeat runs of these three.
- Calls counted from response ids miss retries that produced no event. The provider's own count of requests left is recorded before each attempt.
- Free model listings change; a model that disappears mid-run shows up as provider cuts.
- The pilot (one attempt and one control, `mode=pilot`) checks the instruments and counts for nothing.
